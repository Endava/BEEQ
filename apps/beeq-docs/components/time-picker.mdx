Time pickers combine locale-ordered hour, minute, and second segments with a panel of scrollable columns. People can type a time directly or pick it from the panel, and the component keeps the value in a predictable 24-hour format.

<Note>
  Use a time picker when people need to set a time of day. To pick a date and a time together, pair it with a [date picker](/components/date-picker). For a short list of fixed slots, such as three delivery windows, a [select](/components/select) or radio group is clearer.
</Note>

## When to use

<CardGroup cols={2}>
  <Card>
    <span className="flex items-center mr-2 text-lg font-medium" role="heading">
      <Icon className="mr-2" icon="thumbs-up" iconType="solid" size={20} color="var(--bq-stroke--success)" />
      Use time pickers when
    </span>
    - People need to set a specific time of day, such as a meeting start or an alarm
    - The time must follow local conventions, like segment order and AM/PM labels
    - You need to limit times with business hours or fixed intervals
    - Typing and picking should both be quick and error-free
  </Card>
  <Card>
    <span className="flex items-center mr-2 text-lg font-medium" role="heading">
      <Icon className="mr-2" icon="thumbs-down" iconType="solid" size={20} color="var(--bq-stroke--danger)" />
      Do not use time pickers when
    </span>
    - Only a handful of fixed time slots are available
    - People need to enter a duration longer than a day
    - The value is a relative time, like "in 2 hours"
    - An approximate time of day, like "morning", is enough
  </Card>
</CardGroup>

<Tip>
  Choose [`bq-date-picker`](/components/date-picker) instead of `bq-time-picker` when users select a calendar date rather than a time of day.
</Tip>

## Patterns

<CardGroup cols={2}>
  <CardTile title="Instant selection">
    Each pick in the panel updates the value right away. Use it for most forms, where a time is easy to change later.
  </CardTile>
  <CardTile title="Confirmed selection">
    With `require-confirm`, panel picks stay a draft in the panel, and the field keeps the current time until people press OK or `Enter`. Use it when a new time triggers a costly change, such as rescheduling a booking.
  </CardTile>

## Anatomy

<Frame className="px-4 py-4" caption="Time-picker component anatomy">
  <img className="block dark:hidden" src="/components/images/time-picker/time-picker-anatomy-light.svg" alt="BEEQ Time-picker component anatomy" />

The time picker pairs a labeled, segmented field with a panel of columns, one per time unit. The example uses `second` precision, a 12-hour clock, and a prefix icon to show every part. Keep the label specific and let the locale decide the segment order and labels.

| Part | Element | Description |
|---|---|---|
| **1** | Label | Describes which time the field asks for (`label` slot) |
| **2** | Prefix | Optional icon or text before the time segments (`prefix` slot) |
| **3** | Time segments | The hour, minute, second, and AM/PM controls people focus and edit, ordered for the active locale |
| **4** | Clear button | Removes the current value; hidden with `disable-clear` |
| **5** | Clock trigger | Opens the panel; its icon can be replaced with the `suffix` slot |
| **6** | Panel | The surface that holds the columns and the footer actions |
| **7** | Column | A scrollable list of options for one time unit, under a header that names it and stays in place while the list scrolls |
| **8** | Selected option | The current hour, minute, second, or period, shown with selected styling |
| **9** | Now button | Picks the current time, rounded down to the step; hidden with `disable-now` |
| **10** | OK button | Confirms the selection and closes the panel |

## Design guidelines

<Steps>
  <Step title="Pick the right precision">
    Start with the default `minute` precision. Use `hour` for coarse slots, such as opening hours, and `second` only when seconds matter, such as lap times or logs.
  </Step>
  <Step title="Let the locale drive the format">
    Set `locale` to the product locale, so segment order, separators, and AM/PM labels match what people expect. The clock is 24-hour by default; set `hour-format="12"` when people expect a 12-hour clock.
  </Step>
  <Step title="Constrain the choices">
    Apply `min`, `max`, and step values when business rules are known. Options outside the rules are disabled in the panel, and typed values are clamped when focus leaves the field.
  </Step>
</Steps>

<Note>
  Use steps that divide evenly into the unit, such as 5, 10, 15, or 30 minutes, so the options stay predictable and easy to scan.
</Note>

<Tip>
  Keep the clock trigger visible. It signals that a panel is available and gives pointer users a faster way to pick a time.
</Tip>

## Usage

### Default

Use the default configuration when people need to set an hour and minute. Click the field or the clock icon to open the panel, or type the time directly.

<Note>
  The `value` attribute, `min`, and `max` always use a 24-hour wire format, whatever the display: `HH:mm` at minute precision, `HH:00` at hour precision, and `HH:mm:ss` at second precision.

  A locale-derived format hint, such as `hh:mm`, shows the expected layout before entry starts. On focus, one segment is active. Typing digits replaces that segment, and typing `A` or `P` sets AM/PM. Paste is not supported. See [Keyboard interaction](#keyboard-interaction) for the full key list.
</Note>

## Options

**Allowed `precision` values:** `hour`, `minute` (default), `second`.<br />
**Allowed `hour-format` values:** `24` (default), `12`.<br />
**Allowed `validation-status` values:** `none` (default), `error`, `warning`, `success`.<br />
**Allowed `strategy` values:** `fixed` (default), `absolute`.<br />
**Allowed `placement` values:** `top`, `top-start`, `top-end`, `right`, `right-start`, `right-end`, `bottom`, `bottom-start`, `bottom-end` (default), `left`, `left-start`, `left-end`.

### Labels

Use `labels` to change the column headers, AM/PM labels, button text, and accessible names, for example to translate them. Pass an object, or a JSON string through the HTML attribute. Every key is optional: `hour`, `minute`, `second`, `am`, and `pm` default to the `locale` names, `period` defaults to the AM and PM labels joined by a slash, and the rest default to English.

| Key | Used for | Default |
|---|---|---|
| `hour` | Hour column header and hour segment name | Locale name, e.g. `hour` |
| `minute` | Minute column header and minute segment name | Locale name, e.g. `minute` |
| `second` | Second column header and second segment name | Locale name, e.g. `second` |
| `period` | AM/PM column header and AM/PM segment name | `am` and `pm` joined by a slash |
| `am` | Morning period in the field and the panel | Locale label, e.g. `am` |
| `pm` | Afternoon period in the field and the panel | Locale label, e.g. `pm` |
| `now` | "Now" button text | `"Now"` |
| `clear` | Clear button name | `"Clear"` |
| `confirm` | Confirm button text | `"OK"` |
| `openPanel` | Clock trigger button name | `"Open time picker"` |
| `panelLabel` | Panel name | `"Choose time"` |

### Form integration

`bq-time-picker` submits its current value with the form, in 24-hour format. Use `required` and `form-validation-message` when the time is mandatory; the custom message also applies to incomplete, out-of-range, and off-step values.

<Warning>
  A partly filled field becomes invalid when focus leaves it, even when the picker is optional. The draft stays visible and the last committed `value` is preserved, but native form validation blocks submission until the user completes the time, picks one from the panel, or clears the field.
</Warning>

When focus leaves the field, complete times outside `min` or `max` are clamped to the nearest bound. A disabled time picker is excluded from form data; a read-only one is still submitted.

## Accessibility

- `bq-time-picker` is form-associated and delegates focus, so it participates in native forms and moves focus into its segmented field when the component receives focus.
- The segmented field is a labelled `group` described by the expected format and, when a constraint fails, by the validation message. Each hour, minute, second, and AM/PM control is a `spinbutton` with its own label, limits, value text, and roving tabindex, and exposes `aria-required` when the field is required.
- Each segment sets `aria-invalid="true"` for `validationStatus="error"` and native constraint failures, such as a missing required value or an incomplete, out-of-range, or off-step time. `aria-readonly` and `aria-disabled` reflect the `readonly` and `disabled` states.
- The panel carries `role="dialog"` and is named by `labels.panelLabel` ("Choose time" by default). The panel isn't modal.
- Each column is a `listbox` labelled by its visible header (`aria-labelledby`), so the spoken name matches what people see. Options expose `aria-selected`, and options outside `min`, `max`, or the steps expose `aria-disabled="true"`.
- The component announces the selected time, or that no time is selected, when focus enters the field.
- The panel opens from the keyboard through the segmented field or the clock icon, and moves focus into it; see [Keyboard interaction](#keyboard-interaction) for the keys. Clicking the field opens the panel while keeping focus on the segment.
- In `readonly` mode the segments stay focusable so screen reader users can read the value, but they can't be edited and the panel doesn't open.
- MUST provide a visible label through the `label` slot, so the field has a programmatic name.
- MUST translate `labels` when translating the interface: segment names, button names and the panel name come from it.
- MUST NOT rely on color alone to communicate validation states. MUST pair `validationStatus` with visible error text so screen reader users receive the same feedback as sighted users.

### Keyboard interaction

| Key | Context | Action |
|---|---|---|
| `Tab` | Segmented field | Moves focus to the active segment (one tab stop for all segments) |
| `ArrowLeft` / `ArrowRight` | Time segment | Moves focus to the previous or next segment |
| `Home` / `End` | Time segment | Moves focus to the first or last segment |
| `ArrowUp` / `ArrowDown` | Time segment | Steps the segment value, wrapping around and skipping disabled options |
| `0`–`9` | Hour, minute or second segment | Types digits into the segment and advances automatically when the segment is full |
| `A` / `P` | AM/PM segment (`hour-format="12"`) | Sets the day period and moves to the next segment |
| `Backspace` / `Delete` | Time segment | Clears the segment; `Backspace` then moves focus to the previous segment |
| `Alt+ArrowDown` | Time segment | Opens the panel and moves focus into it |
| `Enter` | Time segment, panel open | Confirms any pending draft and closes the panel |
| `Enter` / `Space` | Clock icon focused | Opens the panel and moves focus to the first column |
| `ArrowUp` / `ArrowDown` | Panel column | Moves to the previous or next option and selects it |
| `Home` / `End` | Panel column | Moves to the first or last option |
| `PageUp` / `PageDown` | Panel column | Moves several options back or forward |
| `ArrowLeft` / `ArrowRight` | Panel column | Moves focus to the adjacent column (mirrored in right-to-left layouts) |
| `Space` | Panel column | Picks the focused option |
| `Enter` | Panel column | Picks the focused option, confirms, and closes the panel |
| `Escape` | Panel column | Closes the panel and returns focus to the field; with `require-confirm`, the draft is discarded |
| Edit keys (digits, `A`/`P`, `Backspace`, `Delete`, `ArrowUp`, `ArrowDown`) | `readonly` | Ignored; segments stay focusable and `ArrowLeft`, `ArrowRight`, `Home` and `End` still move focus |
| Any key | Time picker disabled | Segment key handling is ignored |

### Rules

| Rule | Strength | Verified by |
|---|---|---|
| Provide a visible label through the `label` slot | MUST | manual |
| Set `required` when a time is mandatory so form submission is blocked until a value is set | MUST | automated: `bq-time-picker.e2e.tsx` |
| Set `form-validation-message` to provide a specific message for incomplete, out-of-range, and off-step values | SHOULD | manual |
| Translate `labels` when translating the interface | MUST | manual |
| Pair `validationStatus` with visible error text | MUST | manual |
| Use more than color to communicate validation states | MUST NOT | manual |
| Set `min`, `max`, and step values when business rules are known | SHOULD | manual |
| Use one `hour-format` across a product | MUST | manual |
| Rely on the format hint alone to explain the field | MUST NOT | manual |

| `hourStep` | `hour-step` | Step between selectable hours | `number` | `1` |

| `min` | `min` | Earliest selectable time, in 24-hour format (`HH:mm` or `HH:mm:ss`). Ignored, together with `max`, when it is later than `max` | `string` | `undefined` |
| `minuteStep` | `minute-step` | Step between selectable minutes | `number` | `1` |
| `name` | `name` | Name submitted with the form data (required) | `string` | `undefined` |
| `open` | `open` | If `true`, the panel is visible | `boolean` | `false` |
| `panelHeight` | `panel-height` | Overrides the height of the Time picker panel | `string` | `"auto"` |
| `placement` | `placement` | Position of the Time picker panel | `"bottom" \| "bottom-end" \| "bottom-start" \| "left" \| "left-end" \| "left-start" \| "right" \| "right-end" \| "right-start" \| "top" \| "top-end" \| "top-start"` | `"bottom-end"` |
| `precision` | `precision` | Smallest unit edited and submitted: `hour` → `HH:00`, `minute` → `HH:mm`, `second` → `HH:mm:ss` | `"hour" \| "minute" \| "second"` | `"minute"` |
| `readonly` | `readonly` | If `true`, the value can be read and submitted but not changed | `boolean` | `false` |
| `requireConfirm` | `require-confirm` | If `true`, picks made in the panel (including "Now") are a draft until confirmed with the OK button or Enter. The field keeps showing the committed value until then. Escape or an outside click discards the draft | `boolean` | `false` |
| `required` | `required` | Whether a value must be entered before submitting the form | `boolean` | `false` |
| `secondStep` | `second-step` | Step between selectable seconds | `number` | `1` |
| `skidding` | `skidding` | Skidding between the panel and the field | `number` | `0` |
| `strategy` | `strategy` | Positioning strategy for the panel | `"absolute" \| "fixed"` | `"fixed"` |
| `validationStatus` | `validation-status` | Validation state applied to the field | `"error" \| "none" \| "success" \| "warning"` | `"none"` |
| `value` | `value` | The selected time, in 24-hour format: `HH:mm` (`HH:00` at hour precision) or `HH:mm:ss` at second precision | `string` | `undefined` |

### Invalid combinations

| Combination | Strength | Result |
|---|---|---|
| `min` later than `max` | MUST NOT | Both `min` and `max` are ignored |
| `hour-step` above `23`, or `minute-step` or `second-step` above `59` | MUST NOT | The step is capped at `23` or `59` |
| `hour-step`, `minute-step` or `second-step` below `1` or not a number | MUST NOT | The step is treated as `1` |
| `open` set with `disabled` or `readonly` | SHOULD NOT | The panel does not open |
| An unsupported value for `precision`, `hour-format`, `strategy`, `placement`, or `validation-status` | MUST NOT | A development warning is logged and the default value is used |

### Events

| Event | Description | Type |
|---|---|---|
| `bqBlur` | Fired when focus leaves the Time picker. Moving focus between the field and the panel does not fire it | `CustomEvent<HTMLBqTimePickerElement>` |
| `bqChange` | Fired when the value is committed or cleared | `CustomEvent<{ value: string; el: HTMLElement }>` |
| `bqClear` | Fired when the value is cleared | `CustomEvent<HTMLBqTimePickerElement>` |
| `bqFocus` | Fired when focus enters the Time picker. Moving focus between the field and the panel does not fire it | `CustomEvent<HTMLBqTimePickerElement>` |

<Note>
  - In React, prefix events with `on`: `onBqBlur`, `onBqChange`, `onBqClear`, `onBqFocus`.
  - In Angular, use the event binding syntax: `(bqBlur)`, `(bqChange)`, `(bqClear)`, `(bqFocus)`.
  - In Vue, use the `@` shorthand: `@bqBlur`, `@bqChange`, `@bqClear`, `@bqFocus`.
</Note>
